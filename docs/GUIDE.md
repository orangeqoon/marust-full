# marust（まるスト）の使い方

配信の操作手順です。構造の正本は [ARCHITECTURE.md](ARCHITECTURE.md)、プラグインの約束は [PLUGIN-API.md](PLUGIN-API.md) です。用語は [GLOSSARY.md](../GLOSSARY.md) に準拠します。

## はじめて使う人へ（初級）

丸ストは、OBS から複数のサイト（Twitch・YouTube・ニコ生など）へ**同時に配信する**ための道具です。最初に開くと「最初の設定」の案内が出ます。順番に進めれば、配信できる状態になります（どの手順も「この手順をとばす」ができ、途中で閉じても続きから始まります。あとから「ヘルプ → 最初の設定をやり直す」でも開けます）。

1. **OBS とつなぐ**: OBS のメニュー「ツール → WebSocket サーバー設定」で「WebSocket サーバーを有効にする」にチェックを入れ、ポートとパスワードを丸ストに入れます。
2. **OBS に丸スト用のプラグインを入れる**: 丸ストは専用のプラグイン（obs-multi-rtmp の丸スト用の版）を使います。画面の「OBS にプラグインを入れる」ボタンで入ります（OBS を閉じてから押します。管理者の確認が 1 回出ることがあります。別の版が入っていれば、上書きしてよいか聞きます）。入れたあと OBS を起動して「確かめる」を押します。手で入れたいときは「OBS への入れ方の説明を開く」のリンクから（使っているブラウザで開きます。ファイルは `plugins/ui-standard/shell/guide/obs-plugin.html`）。
3. **サイトを足す**: 足したいサイトを選び、そのサイトの配信設定ページにある「サーバー（URL）」と「ストリームキー」を貼ります。**キーは OBS にだけ渡され、丸ストには保存されません。** 一覧にないサイトも、「その他のサイト」を選べば RTMP の URL とキーで足せます。各サイトの規約で同時配信が許されているかは、ご自身で確かめてください。YouTube とニコ生では、足した直後に「自動枠取り」（配信の枠を丸ストが自動で作る機能）を使うか聞かれます。
4. **回線の確かめ**: 上りの速さを入れると、配信先の数に対して余裕があるかを計算します（丸ストは外の測定サイトへ自分ではつながりません）。
5. **確かめ**: 配信は始めずに、OBS とつながっているか・配信先ができているかだけを確かめます。

### ふだんの使い方（ホーム）
- **配信ボタン**: サイトの名前のボタンを押すとそのサイトの配信が始まり、もう一度押すと止まります（止まっている＝薄い赤、送信中・配信中＝明るい緑）。「配信開始」「全部止める」で全部いっぺんにも操作できます。
- **題名とカテゴリ**: 入れて「全部のサイトに反映」。サイトの行の「題名を送る」が入っているサイトにだけ送られます（ログインが要るサイトがあります）。ログインは「あとで」で構いません。
- **配信先を使う**: そのサイトの配信先をまとめて開始・停止の対象に入れるかどうか。
- **止める（配信の開始・停止）**: ふだんはチェックを外したまま。チェックを入れると、丸ストからは配信の開始・停止ができなくなります。
- **コメント**: 丸ストはコメントを受け取りません（受信は「わんコメ」）。丸ストが行うのは、コメントの送信だけです。
- 「段階」メニューで、初級（複数のサイトへ同時に配信）・中級（まとめて管理）・上級（作る・改良）を選べます。**段階で読み込むプラグインが変わります**: 初級はサイトのプラグインも機能のプラグインも読み込まず、中級でサイトと題名・コメント・タイマー・オーバーレイなど、上級で回線の見張り・ホットキー・Google カレンダーなどと外からのプラグインが使えます。段階を下げても設定と鍵は消えません（上げ直すと元どおり）。段階は配信中でも変えられます（OBS を握る自動枠取りだけ今の状態を保ち、配信が終わると追いつきます）。

### 中級機能の紹介（3 回配信したあと）
- 配信が 3 回終わると、ホームに「新しい機能の紹介」が **1 回に 1 つ**出ます（配信中は出ません）。順番は ニコ生の自動枠取り → YouTube の自動枠取り → 題名・カテゴリのくわしい設定 → コメントを送る → コメントをまとめて送る。使っていないサイト（「題名を送る」がオフのサイト）の紹介は出ません。
- 返事は「設定する」（その機能の画面が開きます）・「あとで」（次に配信が終わったときにまた出ます）・「もう出さない」。
- ホームの下の「中級機能」でも、いつでもオン・オフできます（初めはぜんぶオフ）。オンにすると「開く」ボタンが出ます。ヘルプの「中級機能の紹介を見る」で、紹介をもう一度出せます。
- コメントを送る画面で、書き込めないサイトは選べず、理由が出ます。コメントを受け取るのは今までどおり「わんコメ」です。

以降は、中級・上級・開発者向けのくわしい説明です。

**丸ストを消すとき**: 丸ストの exe を消しても、保存したログインや設定は `%APPDATA%` の中の `marust` フォルダに残ります。すべて消したいときは、そのフォルダも消してください（消すとログインと設定が消えます）。`MARUST_STATE` で保存場所を変えたときは、共有・同期フォルダ（OneDrive など）に向けないでください。

## marust とは

marust（まるスト）は、どの配信先を始めて・止めて・今送信中かを扱う配信のオーケストレーターです。映像の送り方は知りません。最初の実行環境は、この PC の OBS と、その中の OBS エンジン（改良した obs-multi-rtmp）です。

本体は OBS と同じ PC で動きます。画面はブラウザ、Electron のウィンドウ、OBS のドックのどれでも、同じ Web UI を開きます。窓口は `127.0.0.1:18770` だけです。

丸ストは 4 つの層でできています（[ADR 0005](adr/0005-core-first-layer-plugins.md)）。層はフォルダでは決まらず、プラグインが何層目になるかは `host/layer1/plugin-layers.json` の一覧で決まります。
- **核**: 配信エンジンと複数のサイトをつなぐ分かれ道。配信先ごとの開始・停止、全部出す・全部止める、送信中を読みます。
- **一層目（拡張）**: 窓口・CLI・画面・初回の設定案内・サイトの名簿・更新の確認。
- **二層目（管理）**: サイトへ書きにいく管理のプラグイン層。題名の一斉送信・ログイン・枠の自動取り・コメント送信・わんコメとの橋など。
- **三層目（改善）**: 一覧に無い内蔵・他の人のプラグインを入れる仕組み・作者用プラグイン。

公開版の核にはモードは無く、最初から live で動きます。サイトごとの機能はオン・オフで管理します。また、「送信中」（OBS が映像を送れている状態）と「配信中」（サイト上で公開されている状態）を明確に分けて扱います。

## 起動と画面

`streaming/marust` で実行します。初回だけ開発用の Electron が要ります。

```text
npm install
npm run start:app
```

ウィンドウのタイトルは「まるスト / marust」です。中身は `http://127.0.0.1:18770/` です。窓口が開かなかったときは `ui/offline.html` が出ます。文面は「127.0.0.1:18770 で待ち受けられませんでした」。別の marust が同じポートを使っていないか見てください。トレイに残っているときはメニューの「終了」で止めてから、もう一度起動します。配信の送出は OBS 側のままです。

待ち受けが既にあると、同じポートへは開きません。別ポートへは逃げません。

### 画面の見方

上のバーに、ドックの操作とレイアウトがあります。パネルは次です（ドックに出る名前）。

全部止める、配信先、配信開始、題名とカテゴリ、セッション（タイマー）、プラグイン一覧、オーバーレイ、承認待ち、金庫、接続端末、ホットキー、コメント、この画面について。（作者用: モード、本番切り替え、shadow の報告）

プラグインが宣言した画面（タイマー、Google カレンダー、各コメント送信など）も同じドックに並びます。

パネル「題名とカテゴリ」のカテゴリ入力は、Twitch または Kick の配信先を選ぶと、2文字以上の入力を止めて 300ms 後に候補を表示します。候補を選ぶとカテゴリ名が入力されます。

幅が 600 未満だと、ドックを出さず縦に並べます（幅が境をまたぐと読み直します）。`http://127.0.0.1:18770/?view=dock` は縦 1 列の簡易表示で、開き方は「ドック」の節です。パネル 1 枚だけは `http://127.0.0.1:18770/?panel=destinations` のように開きます。`panel` の値は上の名前の id です（`emergency`、`destinations`、`broadcast` など）。知らない値のときはパネル一覧のリンクが出ます。

### ドック

- タイトルをドラッグして並べ替え、タブ化、切り離しができます。
- 「ドックを固定」でドラッグを止めます。もう一度押すと戻ります。
- バーのチェックでパネルの表示を切り替えます。「全部止める」は外しても戻ります。
- 「レイアウトを初期化」は同梱の「標準」を読みます。
- 名前を入れて「保存」。一覧から選んで切り替え。「削除」で消します。名前は 40 文字まで。保存先は `state/data/marust/layouts/` です。

保存と削除には write が要ります。

#### OBS のブラウザドックで開く（`?view=dock`）

同じ画面を OBS のドック枠 1 枚で開くときは、`?view=dock` で縦長の簡易表示にします。

1. OBS のメニュー「ドック」→「カスタムブラウザドックを追加」を開きます（英語版は View → Docks → Add Custom Browser Dock）。
2. 名前に「まるスト」、URL に `http://127.0.0.1:18770/?view=dock` を入れて「追加」します。
3. 初めてはペアリング画面（`/pair`）が出ます。「つなぐ」の「OBS のドック」の手順どおり、ウィンドウの「接続端末」でコードを出しここに入れてつなぎます。
4. つなぐと縦 1 列で、上から 全部止める、配信先の状態（サイト名・状態・再接続回数。キーは出ません）、題名とカテゴリ、タイマー（開始・停止と経過時間）の 4 つだけが出ます。幅 300〜400px で崩れず、文字の大きさは狭い画面と同じです。金庫やモードなど、この PC のウィンドウだけの操作は出ません。権限（read / emergency / write）は他の画面と同じで、write が無いと開始・停止は押せません。
5. `http://127.0.0.1:18770/?view=dock&panel=emergency` のように併せて書くと `panel` が優先します（パネル 1 枚だけの表示は今までどおりです）。

### タスクトレイ、二重起動、自動起動

メインウィンドウの×で、後片付けをして丸スト本体も終了します。最小化は終了ではありません。最小化中はトレイの「終了」でも終了できます。メニューは「ウィンドウを開く」「ブラウザで開く」「全部止める」「終了」です。分離したパネルの窓を閉じるだけでは、本体は終了しません。明示的な画面なし起動は終了指示まで動きます。

同じ PC でもう一度起動すると、新しい窓口は開かず、今のウィンドウを前に出します。

「Windows の起動時に marust を開く」は、パネル「この画面について」にあります。このウィンドウだけ操作でき、最初はオフです。設定は `state/data/marust/app-settings.json` の `openAtLogin` です。読むだけではファイルを作りません。

`package.json` の `version` は `0.2.0` です。配布物は `npm run build` で `dist/marust-win32-x64/marust.exe` です。

配布 exe も同じように起動します。`scripts_core` は exe の中に入っていないので、exe は自分の場所から親フォルダを順に見て探します（ソースからの起動と同じ、リポジトリのルートにある `scripts_core` が見つかります）。見つからないときは起動せず、探した場所と `MARUST_SCRIPTS_ROOT` の案内が出ます。別の場所へコピーした exe では `MARUST_SCRIPTS_ROOT` に `scripts_core` のあるフォルダ（リポジトリのルート）を指定してから起動します。

## つなぐ

秘密の守りは 3 つです（金庫にだけ保存・画面は末尾 4 文字・出口で自動で伏せる）。値は画面とログに出しません。

### この PC のウィンドウ

`npm run start:app` のウィンドウは、起動時に自分用の Cookie を付けます。接続端末の一覧と管理、金庫の一覧と書き込み、承認、ホットキーの保存、モードの変更（作者用）、「Windows の起動時に marust を開く」は、このウィンドウだけです。ブラウザのタブでは出ません（`clientId` が `local-window` のときだけ操作欄が出ます）。接続端末の一覧は、ウィンドウ以外では「表示できません」と出ます。

### ブラウザ

1. ウィンドウの「接続端末」で名前を入れ、権限のチェックを確認し、「新しい端末をつなぐ」。6 桁のコードが出ます。1 回限り、2 分で失効、5 回間違えると無効です。
2. ブラウザで `http://127.0.0.1:18770/` を開きます。まだペアリングしていないと、ペアリング画面（`/pair`）になります。
3. コードを入れて「つなぐ」。成功すると Cookie が付き、ハブが開きます。

read は常に付きます。emergency は最初からチェックされています。write はチェックしたときだけ付きます。

### OBS のドック

OBS のブラウザドック（またはブラウザソース）は、Electron の Cookie を持ちません。

1. ウィンドウで、上と同じようにコードを出します。見るだけなら write は外し、全部止めるも要るなら emergency を残します。
2. そのブラウザで `http://127.0.0.1:18770/pair` を開き、コードを入れます。成功すると `/` に移ります。
3. 1 枚だけ置くときは、ペアリングのあと `http://127.0.0.1:18770/?panel=emergency` のように開きます。

オーバーレイ（配信画面に貼るブラウザソース）は認証なしです。パネル「オーバーレイ」に URL が出ます。形は `http://127.0.0.1:18770/overlay/<プラグイン id>/<名前>` です。タイマーは `/overlay/timer/clock`、同接は `/overlay/ext-viewers/viewers` です。題名と配信中のサイトは `/overlay/overlay-basic/title` と `/overlay/overlay-basic/live-sites` です。下の「オーバーレイ（題名・配信中のサイト）」を見てください。

### Chrome 拡張「Marust」

置き場所はリポジトリの `browser_extensions/marust_extension` です。詳しい読み込みはそこの README です。

1. Chrome の `chrome://extensions` でデベロッパーモードをオンにし、「パッケージ化されていない拡張機能を読み込む」。上のフォルダを選びます。一覧の名前は「Marust」です。
2. marust のウィンドウの「接続端末」で「拡張をつなぐ」。コードが出ます。権限は固定で、ログイン情報を送る `ext-write` と、状態を見る `read` です。
3. 拡張のポップアップにコードを入れて「つなぐ」。「接続中」になれば、トークンは拡張の `chrome.storage.local` にだけ残ります。

Cookie は対象サイトの変化を、サイトごとに 10 秒まとめてから送ります。同じ内容は送りません。ポップアップにはサイトごとのアカウント（既定 `main`）、「今すぐ送る」、最後に送った時刻と件数だけ出ます。値は出ません。送った Cookie は金庫の `cookies.<サイト>-<アカウント>` です（例: サイト `rumble`、アカウント `main` → `cookies.rumble-main`）。

サイドパネルは 5 秒ごとに、配信中の配信先、エンジン、エラー符号を表示します。

作者の環境では、既存の「Live Streaming Sync for NeonTimer」（`browser_extensions/twitcasting_extension`）も並行して動かせます。

### わんコメのブリッジ

プラグインは `onecomme_plugins/onecomme-plugin-marust` です。わんコメの中に 1 本だけ入れます。

1. そのフォルダで `npm install` します（`ws` を入れます）。
2. フォルダを `%APPDATA%\onecomme\plugins\marust` に置き、わんコメのプラグイン一覧で再読み込みします。
3. わんコメを起動した状態で、設定画面 `http://localhost:11180/plugins/dev.orangeqoon.marust/index.html` を開きます。
4. marust の「接続端末」で「わんコメをつなぐ」。権限は `read` と `chat-write` だけです。出たコードを設定画面に入れます。接続情報はプラグインフォルダの `config.json` に保存し、画面には出しません。
5. サイトごとの枠を選んで保存します。空欄のサイトは、名前が `marust:<サイト>` の枠を探します。枠が無いとそのサイトは流しません。

marust からわんコメへは、出所が `onecomme` でない `chat.message` を、その枠へ `POST /api/comments` します。わんコメから marust へは、受け取ったコメントを `chat.publish` で渡します（`source` は `onecomme`）。自分が流したものと、名前が `marust:` で始まる枠は戻しません。

コメントの受け取りはわんコメに任せます。二層目のコメント機能はサイトへの送信（`comment-send`）とわんコメとの橋（`chat-inlet`）です。丸スト自身によるコメント受信（`plugins-author/chat-*`）は作者用です。

接続は `ws://127.0.0.1:18770/ws`、Origin なし、`Authorization: Bearer` です。

### CLI

`streaming/marust/cli/marust.cmd` が、隣の `marust.js` を Node で起動します。先に Agent（`npm run start:app`）が動いていて、一度ペアリングしてあること。Node は PATH から見つかること。

ウィンドウの「接続端末」で「新しい端末をつなぐ」（native 用。コードを CLI に渡します）。

```text
marust.cmd pair
```

トークンは `state/services/marust-cli.json` に保存します。画面とコマンド出力には出しません。

```text
marust pair | status | destinations | start <配信先> | stop <配信先> | stop-all | go <配信先...> --yes | preflight [配信先...] | halt <配信先...> --yes | session show|start <題名>|pause|resume|end | say <本文> --sites a,b --yes | emergency-stop --yes | shadow-report [--days N] [--site X] | describe | doctor
```

`stop-all`（`emergency-stop` は別名）でメイン出力を含むすべての配信先を止めます。`go` / `halt` / `say` は `--yes` が無いと実行しません（`go` は題名やカテゴリを送りません）。Agent が止まっていると「Agent が動いていません」と出て終了します。`--json` で機械向けの出力です。`describe` は `api.describe` の一覧です。`doctor` は下の「診断」と同じ内容です。`--json` で JSON にします。

### AI（MCP）

小さな別プロセスです。marust には native としてつなぎます。書き込みは、この PC のウィンドウで人が承認するまで実行しません。

1. ウィンドウの「接続端末」で「AI（MCP）をつなぐ」。ブラウザのタブにはこのボタンは出ません。権限は `read` と `write` だけです。承認必須です。「全部止める」は渡しません。
2. `streaming/marust` で `node plugins/ai-connect/mcp/server.js pair` を実行し、6 桁を入れます。引数で渡すときは `node plugins/ai-connect/mcp/server.js pair 123456` です。
3. トークンは `state/services/marust-mcp.json` です。出力には出ません。

Claude Code への登録例（marust のフォルダで）:

```text
claude mcp add marust -- node ./plugins/ai-connect/mcp/server.js
```

道具の名前は `marust_` に、メソッド名の `.` を `_` にしたものです。write は承認待ちになり、承認・却下・期限切れ（最大 2 分）のあと結果が返ります。全部止める（emergencyStop）、`secrets.*`、`clients.*`、承認の承認と却下、`engine.setKey`、ウィンドウ専用の操作は道具にしません。

### Stream Deck とホットキー

Stream Deck 用のプラグインは作っていません。Stream Deck の「システム」→「開く」で `cli/marust.cmd` を選び、引数をボタンごとに 1 つ入れます。例は `cli/README.md` です（`go` と `halt` には `--yes`、全停止は `stop-all`）。

ホットキーはパネル「ホットキー」です（上級の機能です。メニューの「機能」で「ホットキー」を入れると、キーが登録されます。切っているあいだは、キーも効きません）。編集と「保存」はウィンドウだけです。既定は空で、何も登録しません。保存先は `state/data/marust/hotkeys.json` です。割り当てられるのは read と write のメソッドと、「全部止める」（`broadcast.stopAll` / `engine.emergencyStop`）です。ホットキーの「全部止める」は 1 回押しですぐ止まります。

### 権限の意味

| 権限 | 意味 |
| :--- | :--- |
| `read` | 状態を見る。配信前チェック、一覧、コメントの閲覧 |
| `write` | 配信先の開始と停止、題名の送信、セッション、レイアウトの保存など。ブラウザではチェックしたときだけ |
| `emergency` | 全部止める（`broadcast.stopAll` / `engine.emergencyStop`）だけに使う区分 |
| `ext-write` | 拡張が Cookie とキャプチャを金庫へ送るだけ。WebSocket の API は使えない |
| `chat-write` | `chat.publish` だけ。わんコメ用。他の write は使えない |

ウィンドウ以外の write / emergency / ウィンドウ専用の操作は、`state/logs/marust/api-YYYYMMDD.jsonl` に「いつ・どの端末・何を・結果」を残します。引数の値は残しません。

承認待ち（`requiresApproval`）の write は、すぐには実行しません。パネル「承認待ち」に出します。期限は 2 分です。MCP は必ず承認待ちです。`chat.publish` は承認待ちにせず、記録だけ残します。

## オン・オフ

配信開始は最初から使えます。サイトの「題名を送る」「コメントを書き込む」「自動枠取り」などはオン・オフで、保存先は `state/services/marust-modes.json`（`live`＝オン、`legacy`＝オフ）です。公開版の核にはモードは無く、最初から live で動きます。作者用のモード（shadow など）は後述の「作者向け」の節にあります。

## 金庫（秘密の保管場所）のしくみと写し

秘密の守りは 3 つです（暗号化した金庫にだけ保存・画面は末尾 4 文字・出口で自動で伏せる）。

- 金庫は Electron の `safeStorage`（Windows のユーザーごとの鍵）で暗号化し、暗号文だけを `state/services/marust-vault.json` に置きます。Electron の外（`node main.js` で直に起動した場合）では秘密を保存できません（画面に「この起動では秘密（ログイン情報）を保存できません」と出ます。丸ストのアプリから起動してください）。
- **金庫ファイルの写しは、同じ PC・同じ Windows ユーザー・同じアプリ名（`marust`）でしか戻せません。** 鍵はアプリの保存場所（`%APPDATA%\marust\Local State`）にあるためです。別の PC へ移すときは、ウィンドウの「バックアップと引っ越し」の**引っ越しファイル**（合言葉で暗号化）を使ってください。
- 暗号文の置き場は差し替えられる作りです（口 `vault-store@1`。内蔵プラグインだけ）。同梱の差し替えはありません。

## セッション

セッション（配信の時間の記録）は、三層目のプラグイン（`plugins/session`）が受け持ちます。核にはセッションの概念は無く、セッションのプラグインが核の合図（`broadcast.started`、`broadcast.stopped`）を受けて記録します。

配信を始めたとき（核の合図 `broadcast.started`）に自動でセッションを始めます（すでにセッションが進行中なら何もしません）。そして、すべての配信先を止めたとき（核の合図 `broadcast.stopped` の `all: true`）に自動でセッションを終えます（理由は `all-stopped`）。終わりのイベントは `session.ended` です。

手動で始める道もあります。画面のセッション操作や、CLI の `marust session start <題名>`（API の `session.start`）で手動で始めることができます。一時停止（`session.pause` / CLI `session pause`）、再開（`session.resume` / CLI `session resume`）、終了（`session.end` / CLI `session end`）、題名の変更（`session.retitle`）も行えます。状態は `session.view`（CLI `session show`）で確認でき、記録はプラグインのデータ置き場（`state/data/marust/plugins/session/session.json`）に保存されます。

## 全部止める

パネル「全部止める」（パネル id: `emergency`）のボタンです。

止め方は「全部止める」と「配信先を止める」の 2 つです。非常停止は「全部止める」に一本化されました（長押しなし、赤の状態なし）。1 クリックですぐに止まります。

メイン出力（`obs-main`）を含むすべての配信先を停止します。押しまちがいは確認画面ではなく置き場所（配信開始とは別の場所）で守ります。

ホットキーに「全部止める」（`broadcast.stopAll` / `engine.emergencyStop`）を割り当てたときは 1 回押しですぐに実行されます。

OBS 上にも丸スト用プラグインによる「全部止める」ボタンがあり、押されるとメイン出力を含めて全配信先が止まります。OBS 側で押されると、丸ストの画面に「OBS 側で全部止めるが押されました」と出ます。

## サイトの困りごと

二層目の仕事（題名の一斉送信、ログイン、枠取りなど）がサイト側でうまくいかないときは、全サイト共通の合図「サイトの困りごと」（`site.trouble`）にまとめられます。

種類は「ログイン切れ」「回数の上限」「つながらない」の 3 つです。サイトの困りごとが起きても、映像の配信（送信中）は止めません。一時的な失敗は自動でやり直します。ログイン切れはそのサイトの二層目の仕事だけを止め、ホーム画面に 1 行で知らせます。

## コメント送信

パネル「コメント送信」（二層目プラグイン `comment-send`）に本文欄、送るサイトのチェック、送信ボタンがあります。送信中はボタンを押せません。Enter でも送ります。結果が `ok: true` のあと、本文欄は空になります。結果はサイトごとに ✓ / ✗ です。送れるサイトが無いときは「送れるサイトはまだありません。」です。

API は `chat.send`（write）です。本文は 1〜200 文字、サイトは 1〜10 です。承認待ちになる端末は、すぐには送らずパネル「承認待ち」に出ます。`chat-write` だけの端末は `forbidden` です。受け口が無いときは `unavailable` です。送った本文は `chat.message` には重ねません。

CLI は `marust say "<本文>" --sites a,b --yes` です（`marust.cmd say` も同じコマンドです）。`--yes` が無いときは「コメントを送るには --yes が必要です」と出て、外へは送りません。1 サイトあたり 1 秒に 1 通までです。

YouTube・Twitch・Kick は、題名更新用のトークン（`youtube.oauth` / `twitch.oauth` / `kick.oauth`）に、次の権限が足してある必要があります。この送信プラグインはブラウザの再認証をしません。

| サイト | 必要な権限 |
| :--- | :--- |
| YouTube | `https://www.googleapis.com/auth/youtube` または `https://www.googleapis.com/auth/youtube.force-ssl` |
| Twitch | `user:write:chat` |
| Kick | `chat:write`（あわせて `user:read`。ユーザー取得に使います） |

コメントの受け取りはわんコメに任せます。丸ストが行うのは送信とわんコメとの橋（`chat-inlet`）です。

## Twitch レイド

プラグイン `raid-twitch` が、配信停止（`stream.stopping`）のときに Twitch へレイドします。「全部止める」（reason が `emergency` または `all: true`）のときはレイドしません。秘密も Helix も触りません。

live だけがレイドを送ります。live には金庫の `twitch.oauth`（`client_id` と `access_token`）が要ります。トークンの更新はこのプラグインではしません。

候補の順は、おすすめ（データ置き場の `raid-suggested-channels.json` の `channels`）のうち配信中の人で、視聴者が最少の人。いなければ、相互フォローのうち配信中の人で、視聴者が最少の人。相互フォローは `raid-cache.json` にあり、約 180 日より新しければ Helix の followed / followers は呼びません。全員オフライン、または候補が無いときはレイドしません。

おすすめの入れ方は API `plugin.raid-twitch.setSuggested`（write）です。`channels` にログイン名の配列を渡すと、`raid-suggested-channels.json` に `{ channels: [...] }` で残します。パネル「Twitch レイド」はモード、ログイン情報の有無、次の候補、最後の結果を見ます。パネルに候補の編集欄はありません。

## オーバーレイ（題名・配信中のサイト）

プラグイン `overlay-basic` です。認証なしです。表示だけで、外へは出ません。

- `GET /overlay/overlay-basic/title` … 今のセッションの題名です。field は `title`（文字列。長いときは 200 文字まで）。`session.ended` のあとは空です。SSE は同じ名前の `/events` です。
- `GET /overlay/overlay-basic/live-sites` … 配信中のサイト名を 1 つの文字列にしたものです。field は `sites`。区切りは ` · ` で、文字コード順です。`engine.target.changed` のたびに配信先一覧を見ます。`engineState` が `live`、または `siteLive` が true の行だけです。一覧が取れないときは、イベントの `name` を同じ形の文字列にします。SSE は `/events` です。

数値やオブジェクトは来ません。秘密の名前も field に載せません。背景は暗いです。


## ログの整理

配信や操作の記録は JSONL です。置き場所は `state/logs/marust/` の `shadow-`、`engine-`、`api-`、`vault-`、`emergency-` と、各プラグインのデータ置き場（`state/data/marust/plugins/<id>`）にある `shadow-` です。日付は端末のローカル暦で、ファイル名は `接頭辞-YYYYMMDD.jsonl` です。

寿命の既定は 30 日です。監査の `api-`、`vault-`、`emergency-` は 180 日です。`shadow-` と `engine-`（プラグインの shadow も含む）は `ordinaryDays`、監査の 3 つは `auditDays` です。ファイルは `state/data/marust/log-retention.json` です。値は 1 から 3650 の整数です。欠けている、範囲外、整数でない、JSON が壊れている項目だけ、その項目を既定に戻します。

1 ファイルが 20 MB を超えた追記は、同じ日の `-2`、`-3` に分けます。すでに書いた行は分割しません。1 行が上限より大きくても、その行は割らずに書きます。

整理は起動時と、その後 24 時間ごとです。消すのは、ファイル名の日付が寿命より前のものだけです。ちょうど寿命の日と、今日の分は残します。今日の分は大きくても消しません。想定外のファイル名は残します。ログの中身は読まず、画面にも出しません。

## 設定の書き出し・読み込み（入らないもの）

パネル「設定の書き出し」です。この PC のウィンドウだけが使えます。ブラウザや他の端末は `forbidden` です。

書き出すのは 1 つの JSON です。`schemaVersion` は 1 だけです。ファイル名は `marust-settings-YYYYMMDD.json` で、日付は東京です。中にあるのは次だけです。

- レイアウト（最後に開いた名前と、保存済みの中身）
- モード（`marust-modes.json`。`legacy` / `shadow` / `live` だけ）
- ホットキー（accelerator、method、params、label）
- 配信先の紐付けと `desired`（題名、カテゴリ、live）。`actual` は入れません
- プラグインの `config.json`
- 自動起動（`openAtLogin`）

入れないものは、金庫の中身、Cookie、トークン、端末の一覧とそのハッシュ、ログです。鍵の名前に `cookie` / `token` / `secret` / `password` / `vault` / `authorization` / `credential` / `bearer` を含むもの、および項目名がちょうど `key` のものは、レイアウトの data、ホットキーの params、プラグイン設定から落とします。

「書き出す」は、クリックの直後に保存ダイアログを開き、そのあと JSON を書きます。ダイアログが無い、または中断以外で失敗したときは、ブラウザのダウンロードに落とします。「読み込む」はファイルを選び、先に一覧だけ出します。一覧は項目名と件数と名前で、値は返しません。選んで「反映する」と、選んだ区分だけ置き換えます。`schemaVersion` が 1 以外のときは拒否し、控えも書きません。

反映の前に、今の設定を同じ形式で `state/data/marust/backups/` に控えます。時刻は東京です。配信先は一覧を置き換えますが、同じ id の `actual` はディスクに残します。セッションは変えません。入っていないプラグインの `config.json` だけ消し、ログなど他のファイルは残します。自動起動は `{ openAtLogin }` にし、Windows の起動登録も更新します。

## 診断・marust doctor

パネル「診断」と、CLI の `marust doctor` です。中身は API `diagnostics.run`（read）と同じです。`--json` を付けると JSON です。

見るのは、Agent の稼働時間、窓口（`127.0.0.1:18770`）、プラグインごとの状態とモード、OBS エンジン、金庫が使えるか、ログの容量、状態ファイル、直近のエラー符号です。値と秘密は返しません。金庫の中身は見ません。ファイル名も入れません。

エラーの項目が無ければ成功です。warn だけでも成功です。直近のエラー符号は短い符号だけで、最大 20 件です。診断は 4.5 秒で打ち切り、そこまでの項目を返します。

Agent が止まっていると「Agent が動いていません」と出て、`npm run start:app` を案内します。ペアリングが無いときは `marust pair` を案内します。

## 困ったとき

### Agent が動かない

- CLI は「Agent が動いていません」。`streaming/marust` で `npm run start:app` を先に動かします。
- ウィンドウが「まるストを表示できません」なら、`127.0.0.1:18770` を開けていません。別の marust はトレイの「終了」で止めてから起動し直します。
- 画面の「切断（再接続中）」は、WebSocket が切れているときです。ブラウザなら、ペアリングの Cookie が無いと `/` はペアリング画面に戻ります。

### ペアリングできない

- コードは 1 回、2 分、5 回失敗で無効です。ウィンドウで出し直します。
- 「新しい端末をつなぐ」「拡張をつなぐ」「わんコメをつなぐ」「AI（MCP）をつなぐ」は、Electron のウィンドウだけに出ます。
- 拡張は Origin が `chrome-extension://<その拡張の id>` でないと拒否します。トークンだけでは別の拡張から使えません。
- CLI と MCP とわんコメは Origin を付けません。ブラウザの `/pair` は Origin が `http://127.0.0.1:18770` か `http://localhost:18770` でないと拒否します。

### OBS エンジンが非対応

パネル「エンジン」が「接続中・エンジン非対応（足りない: …）」のとき、vendor 名 `obs-multi-rtmp` の要求が足りません。marust が揃っていると見る名前は、読み取り `list_capabilities` / `list_targets` / `get_target_status` / `get_target_config`、書き込み `start_target` / `stop_target` / `set_target_enabled` / `set_target_service_settings` / `create_target` / `delete_target` です。

接続先は `state/services/obs-config.json` です。失敗しても 30 秒ごとに繋ぎ直します。パスワードはログに出ません。未接続のあいだ、全部止めるは押せません。

配信前チェックの `engine-unsupported` は「エンジンが非対応です」（error）。`engine-disconnected` は「エンジンが未接続です」。

### 金庫が使えない

「金庫」に `unavailable` と出るとき、暗号化の実装が使えません。Electron の中では `safeStorage`、それが使えなければ PowerShell の DPAPI です。どちらも使えなければ、起動はしますが読み書きは `unavailable` です。テスト用の偽の暗号化は、通常の起動では使いません。

名前の一覧、保存、削除はウィンドウだけです。ブラウザでは一覧を出しません。値は一覧に出ません。

### YouTube・Twitch・Kickのログインが切れた

Electron のウィンドウの「金庫」にある「結び直す」ボタンを押し、確認後に既定のブラウザで認証します。認証中は、金庫に保存された `client_id`・`client_secret`・`redirect_uri` だけを使い、トークンの値は画面にもログにも出しません。成功すると同じ金庫名（`youtube.oauth` / `twitch.oauth` / `kick.oauth`）へ保存します。

- `port-in-use`: 他のソフトが同じ登録済みポートを使っています。閉じてからやり直します。
- `redirect-uri-unsupported`: `redirect_uri` が `127.0.0.1` か `localhost` の明示的なポートではありません。サイトに登録した URI と金庫の値を確認します。YouTube と Kick は `redirect_uri` が要ります。Twitch は無いときは `http://localhost:3000` を使います。
- 認証が時間切れになった: 3 分以内にブラウザで完了しなかった状態です。もう一度ボタンを押します。
- 結び直しは Electron のウィンドウだけで使えます。ブラウザ、拡張、MCP からは `forbidden` です。

### 承認待ちが消えない

- 承認と却下のボタンは、Electron のウィンドウの「承認待ち」だけに出ます。ブラウザでは一覧が見えてもボタンが無く、期限まで残ります。
- 期限は 2 分です。行に `expiresAt` が出ます。過ぎると一覧から外れます。MCP は最大 2 分待って、承認・却下・期限切れのどれかを返します。
- ウィンドウなのにボタンが無いときは、write が無い端末です。このウィンドウ自体は操作できます。別のタブを見ていないか確認します。
- `chat.publish`（わんコメ）は承認待ちに入りません。ここに残るのは、承認必須の write です。

## OBS とつなぐ（R3）
パネル「OBS とつなぐ」（メニュー: ツール）で、丸ストと OBS をつなぎます。
1. OBS のメニュー「ツール → WebSocket サーバー設定」で、「WebSocket サーバーを有効にする」にチェックを入れる。
2. 表示されるポート（初期値 4455）とパスワードを、パネルの欄に入れて「保存してつなぐ」。パスワードは丸ストの金庫に暗号化して入り、画面には二度と出ません（空のまま保存すると今のままです）。
3. 「つないでみる」で、OBS につながるかと、丸スト用の OBS プラグイン（改造した obs-multi-rtmp）が入っているかを確かめられます。配信は操作しません。

## OBS プラグイン（obs-multi-rtmp の改造版）
入っていない・古いと言われたら、初回の画面の「OBS にプラグインを入れる」ボタンを押します（押さないかぎり丸ストは入れません）。手で入れるなら、`streaming/obs-multi-rtmp/dist/` のビルド済みの dll を OBS のプラグインフォルダへ入れ、OBS を再起動します（OBS 側の手順は `streaming/obs-multi-rtmp/MARUST.md`）。

## サイトを足す・送る／送らない・ログインの準備（M2）
- **サイトを足す**（ツール → サイトを足す）: サイトを選び、そのサイトの配信設定ページに出る「サーバー（URL）」と「ストリームキー」を貼ると、OBS に配信先ができます。キーは OBS にだけ渡し、丸ストには保存しません。**同時配信が許されているかは、そのサイトの規約で、あなた自身で確かめてください**（画面に規約へのリンクがあります）。OBS に作るには、先に「OBS とつなぐ」で、丸ストから OBS を操作できるようにします。
- **送る／送らない**（サイト別の状態）: 「送る」にしたサイトにだけ、題名とカテゴリが実際に反映されます。基本の 3 サイト（Twitch・YouTube・ニコ生）のほかは「試験中」で、「試験中のサイトも表示する」をオンにしたときだけ見えます。
- **ログインは 2 段**: ① ストリームキーだけ（ログイン不要。映像は全部のサイトへ流れる）。② ログインする（題名・カテゴリの一斉反映、コメント送信）。②は中級者向けです。
- **ログインの準備（YouTube・Twitch・Kick）**: あなた自身の「開発者アプリ」を作り、クライアント ID・クライアントシークレット・戻り先（`http://localhost:3000/` のような、この PC を指す URL）を、「サイト別の状態」の「ログインの準備」に入れます。値は金庫に暗号化して入り、画面には出ません。入れたら続けてブラウザが開くので、認証します。
- **ニコ生などの Cookie**: ブラウザの拡張機能（`browser_extensions/marust_extension`）で取り込みます。

## 【作者向け】モード・NeonTimer からの移行・内部機能

公開版には含まれない、作者の環境（NeonTimer との並行稼働や移行）および作者用プラグイン（三層目 `plugins-author/`）に関する説明です。

### モード（author-modes）

公開版の核にはモードは無く、最初から live で動きます。モード（legacy / shadow / live）は作者用プラグイン `plugins-author/author-modes/` が提供します。設定ファイルは `state/services/marust-modes.json` です。パネル「モード」でプラグインごとに切り替えます（`modes.list` / `modes.set` / `modes.setDefault`）。

### 今の NeonTimer との関係

作者の PC では、常駐中の本番 NeonTimer（`streaming/NeonTimerApp`）と並行して marust が動きます。配信開始は最初から使えます。サイトの機能（題名を送る・コメント送信・自動枠取り）は既定でオフです。`:18766`（NeonTimer の Cookie 受け口）は変えていません。marust の窓口は `127.0.0.1:18770` だけです。

### NeonTimer からの移行

サイトの題名更新を、NeonTimer のラッパから marust の `site-<site>` へ移す手順です。配信していないときに行います。秘密の値は画面にもログにも出ません。

1. この PC のウィンドウの「金庫」で「NeonTimer から取り込む」。一覧から選んで実行するとコピーします。元のファイルは消えません。
2. パネル「モード」で、移したい `site-<site>` を shadow にする。題名を送り、`state/logs/marust/shadow-YYYYMMDD.jsonl` の記録を見る。shadow のあいだは外へ出ません。
3. 記録が意図と合ってから、その `site-<site>` を live にする。
4. NeonTimer 側の同じ処理を止める。

### 最初の本番切り替え（Rumble）

1. 金庫に Rumble の API キーを入れる（`rumble.livestream-api`）。
2. Cookie は拡張「Marust」から金庫の `cookies.rumble-main` へ送る。
3. 「配信先」で配信先 id に `rumble-main`、サイトに `rumble`、キーに `per-broadcast` を入れてリンク。
4. 「配信開始」でチェック（`broadcast.preflight`）。
5. パネル「モード」で `slot-rumble`、`broadcast`、`obs-engine` を shadow にして配信開始を試す。
6. 記録を確認後、live にする。
7. NeonTimer 側の Rumble 処理を止める。

### 本番切り替えの案内パネル

ドックの名前は「本番切り替え」。サイトを選んで「再表示」すると、`golive.check`（read）がログイン、配信先、配信前チェック、shadow、モード、NeonTimer の 6 項目を判定します。

### shadow の報告

パネルの名前は「shadow の報告」です。CLI は `marust shadow-report [--days N] [--site X] [--json]`、API は `shadow.report`（read）です。`state/logs/marust/shadow-YYYYMMDD.jsonl` などの直近の記録を集計して表示します。

### kukulu のプラグイン

`kukulu-sleep` は睡眠タイトルのときだけ枠を返上し、`kukulu-port` は睡眠タイトルでないときに枠を取ります。`site-kukulu` は題名の更新を行います。

### NicoAutoCaster の /status

NicoAutoCaster に `GET /status` があり、メモリ上の `programId`、`status`（`ON_AIR` / `TEST` / `ENDED` / `UNKNOWN`）、`updatedAt` を返します。読み取り専用です。

### 回線の見張り（signal-monitor）

`signal-monitor` は OBS の `GetStreamStatus` を数秒ごとに読み、出力の輻輳、スキップ率、再接続から `ok` / `degraded` / `bad` を判定します。上級・開発者モード向けのプラグインです。
